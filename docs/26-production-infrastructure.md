# 生产基础设施与上线清单

日期：2026-10-20
状态：个人开发者精简生产方案
相关：[技术架构](./09-technical-architecture.md)、[成本模型](./24-cost-model.md)、[账号与支付可行性](./25-account-and-payment-feasibility.md)

## 1. 结论

### 光有一台服务器够不够？

**作为早期计算节点够了，作为完整生产系统不够。**

一台服务器可以运行：

- Fastify 语音网关；
- Nginx/Caddy；
- PostgreSQL；
- 日志和监控 agent；
- 静态隐私政策/帮助页。

但它不能同时充当：

- 唯一的数据存储；
- 唯一的备份；
- 高可用数据库；
- 自建对象存储的可靠副本；
- 密钥管理与安全审计的全部基础。

早期不必购买 Kubernetes、负载均衡集群或大型客服系统，但必须把**数据库持久化、备份、密钥、监控**从“服务器本地磁盘”中分离出来。

### 当前阶段要买 OSS 吗？

**免费本地首发之前不必买。云备份功能开始开发时再买。**

当前账本存在手机 SQLite；服务端不保存录音和转写。云备份尚未实现，因此现在不需要对象存储。等 M4 云备份开始开发，再购买私有 OSS/COS/S3 兼容对象存储。

### MinIO 还是 OSS？

个人开发者第一版建议使用**云厂商托管对象存储**，例如阿里云 OSS、腾讯云 COS 或其他 S3 兼容服务。

MinIO 适合：

- 本地开发和测试；
- 有明确数据主权需求；
- 有人维护磁盘、扩容、快照、容灾和升级；
- 后续需要自建对象存储集群。

MinIO 不适合：

- 只有一台服务器；
- 把同一块磁盘当成唯一备份；
- 团队没有运维经验，却要承担数据可靠性；
- 为了省托管费用而牺牲恢复能力。

## 2. 推荐的精简架构

```text
手机 App
  -> HTTPS / WSS
  -> 域名 + 反向代理
  -> Fastify 语音网关
       -> 火山 ASR / DeepSeek / 备用供应商
       -> PostgreSQL
            - 匿名安装额度
            - 用户与令牌（未来）
            - 会员 entitlement（未来）
            - 备份元数据（未来）
       -> 私有对象存储（未来）
            - 加密备份快照
            - 不保存音频和转写正文
```

音频只在请求生命周期内存在，处理结束后删除。对象存储只用于用户加密账本快照，不用于存放录音。

## 3. 现在就需要准备的东西

### 3.1 服务器

现有服务器作为应用节点即可。最低需要确认：

- 公网 IP 或稳定入口；
- Linux 常用发行版；
- Node.js 22；
- Docker 或 systemd；
- 反向代理 Nginx/Caddy；
- 只开放必要端口，至少 80/443，SSH 限制来源；
- 自动重启和健康检查；
- 服务器快照与基本监控。

第一版建议 2 vCPU、2–4 GB 内存作为起点，但最终以真实并发和 ASR 连接数测试为准。ASR 是外部 API，不需要 GPU。

### 3.2 域名、HTTPS 和备案

至少准备：

- API 域名，例如 `api.example.com`；
- 隐私政策/帮助页域名，例如 `www.example.com` 或独立页面；
- DNS 解析；
- HTTPS 证书；
- WSS 反向代理；
- 中国内地服务器需要评估 ICP 备案和 App 备案要求；
- 商店审核需要可公开访问的隐私政策和支持入口。

证书可以先用 Let's Encrypt 自动续期，不一定要单独购买商业证书。

### 3.3 PostgreSQL

免费本地首发仍需要服务端持久化语音额度和风控信息。当前 `InMemoryDailyVoiceQuota` 重启会清空、多实例不共享，不能直接当作正式服务。

推荐：

- 预算允许：买同区域的基础云数据库 PostgreSQL；
- 预算很紧：服务器 Docker/本地 PostgreSQL，但必须每日备份到服务器之外；
- 迁移到数据库后，额度按安装哈希和日期原子计数；
- 为数据库建立自动备份、恢复演练和保留周期。

不要用手机 SQLite 代替服务端数据库，也不要把服务器本地 PostgreSQL 文件当作唯一备份。

### 3.4 AI 供应商

需要开通并管理：

- 火山流式 ASR；
- DeepSeek 结构化；
- SiliconFlow HTTP 备用；
- 供应商额度、计费、并发限制和超时；
- 每日成本告警；
- 供应商 Key 轮换和最小权限。

Key 只放服务端环境变量或 Secrets Manager，不进入 App、构建产物和 Git。

### 3.5 监控与日志

最低要有：

- 服务健康检查；
- HTTP/WSS 错误率和 P50/P95 延迟；
- ASR、LLM 调用数和失败码；
- 每日 AI 成本；
- 进程崩溃和重启告警；
- 日志脱敏：不记录录音、转写、账单正文、备注和 token。

可以先用服务器日志加一个简单的 uptime 监控，后续再接错误聚合服务；不要因为“日志很重要”就把敏感账本正文写进日志。

### 3.6 客服与商店材料

客服第一版不需要买大型系统，通常准备：

- 支持邮箱；
- 可访问的帮助/FAQ 页面；
- 隐私政策和用户协议；
- 数据删除和账号删除说明；
- 错误反馈入口；
- App Store 和安卓商店所需支持 URL。

微信客服、工单系统和自动机器人可以等真实咨询量起来后再接。

## 4. 存储怎么分层

| 数据 | 放在哪里 | 是否现在需要 |
| --- | --- | --- |
| 用户账本、分类、设置 | 手机 SQLite | 已有，作为主数据 |
| 语音临时文件 | 手机/网关临时目录 | 需要，请求结束立即删 |
| 用户、额度、令牌、权益、备份元数据 | PostgreSQL | 首发前建议有持久化额度库 |
| 录音和转写正文 | 不长期保存 | 不买存储 |
| 加密账本快照 | 私有 OSS/COS/S3 | 做云备份时再买 |
| KMS 密钥、供应商密钥 | Secrets Manager/KMS | 云备份和支付前补齐 |
| 服务器日志 | 本地或日志服务 | 需要，注意脱敏 |

### 对象存储要求

启用云备份时，对象存储必须：

- 私有 Bucket；
- 服务端加密或应用层加密；
- 禁止公共读；
- 通过后端签名访问；
- 按 `userId` 隔离；
- 有版本/生命周期策略；
- 可以通过 checksum 校验；
- 删除账号时能清理对应用户对象。

## 5. MinIO 与 OSS 的取舍

| 方案 | 优点 | 代价 | 适用 |
| --- | --- | --- | --- |
| 云厂商 OSS/COS | 托管、低运维、私有 ACL、生命周期、云内传输快 | 按量收费，存在云厂商绑定 | 个人开发者首版 |
| MinIO 自建 | S3 兼容、可控、可本地 | 要自己管磁盘、副本、备份、升级和故障 | 本地开发、特殊部署 |
| 服务器本地目录 | 最简单、临时成本低 | 单点故障，不能算备份 | 临时导出、测试 |

单服务器上的 MinIO 仍然是单点。除非有至少两块独立磁盘、异地备份和恢复演练，否则不能把它当作“云备份可靠性”。

## 6. 支付与会员基础设施

### iOS 内购

Apple 个人开发者账号就绪后，需要：

- App Store Connect 内购商品；
- 付费应用协议；
- 税务和银行账户；
- Apple 收据校验；
- App Store Server Notifications；
- 恢复购买；
- 退款、撤销和会员到期状态；
- 内部 `userId` 和 entitlement 表。

### 微信/支付宝 APP 支付

不在当前首发范围。等有商户主体后，再准备：

- 商户号；
- 经营类目和资质；
- 结算账户；
- 商户号与应用绑定；
- 支付回调签名校验；
- 幂等订单表；
- 退款和财务对账。

### 客服与支付的关系

支付上线后，客服处理会明显增加，至少需要：

- 未到账/重复扣款处理流程；
- 恢复购买说明；
- 退款入口或人工流程；
- 账号和 entitlement 查询；
- 数据删除与注销流程。

## 7. 现在不要急着买

- Kubernetes；
- 多台应用服务器；
- 独立负载均衡；
- Redis；
- GPU 服务器；
- MinIO 集群；
- CDN；
- 企业级客服系统；
- 短信平台；
- 微信/支付宝商户系统。

这些能力应在真实用户量、并发、留存和付费需求出现后再评估。

## 8. 分阶段准备

### 阶段 A：免费本地首发

- 现有服务器 + 域名 + HTTPS/WSS；
- Fastify 网关；
- PostgreSQL 额度与风控；
- 火山/DeepSeek/SiliconFlow；
- 日志、监控和成本告警；
- 隐私政策、帮助页、支持邮箱；
- 本地 JSON/CSV 导出与恢复。

### 阶段 B：云备份

- 私有 OSS/COS；
- KMS/Secrets Manager；
- 备份元数据表；
- 加密、checksum、版本和删除；
- 恢复演练。

### 阶段 C：iOS 会员

- Apple 内购；
- entitlement；
- 收据校验和恢复购买；
- 退款状态。

### 阶段 D：安卓支付与规模化

- 经营主体和商户资质；
- 微信/支付宝 APP 支付；
- 订单、退款和财务对账；
- 多实例、负载均衡和更完整的可观测性。

## 9. 上线前最小检查表

- [ ] 域名和 HTTPS/WSS 可用。
- [ ] 服务器关闭多余端口。
- [ ] 密钥不在客户端和 Git。
- [ ] 语音额度持久化。
- [ ] 每日 AI 成本可查看并告警。
- [ ] 录音和转写请求结束即删除。
- [ ] 日志不含账单正文和 token。
- [ ] 数据库和配置有异地备份。
- [ ] 隐私政策、用户协议、支持和删除入口可访问。
- [ ] 恢复流程在一台全新环境实际演练过。
