# 声账实施路线图

## 1. 推进原则

- 每个里程碑都必须能独立运行和验收，不以“代码写完”代替完成。
- 先打通本地核心闭环，再接真实语音和微信；外部账号不阻塞本地开发。
- 每次只允许一个高风险集成处于进行中，避免同时调试数据库、语音和登录。
- 原型是交互事实来源，技术方案是工程事实来源；两者冲突时先修订文档。
- 每个阶段结束都更新 `docs/HANDOFF.md`、测试和验收记录。

## 3. M0：产品原型与技术基线

### 已完成

- 产品定位、MVP 范围和视觉方向。
- 可点击原型，含语音一步录音、账本、统计、分类、登录、备份和异常状态。
- 原型自动回归 19 项，页面截图和布局审计。
- pnpm workspace、Expo 移动端骨架、Fastify API 骨架、共享 contracts/domain 包。
- GitHub Actions 基础 CI。
- 仓库级 `AGENTS.md`。

### 已完成补充

- 技术架构、数据模型、API、仓库结构、开发环境、实施路线、测试发布、决策记录、UI 交接和资产索引均已落盘。
- Node.js 已是 22.19.0；全仓 typecheck/test 通过；Expo Doctor 20/20；iOS bundle 导出成功。
- 高保真 UI 采用代码稿 + 导出 PNG 的方式，在 M5 与功能开发并行推进。

### 退出标准

- `pnpm typecheck` 与 `pnpm test` 通过。
- 文档索引、状态板和 README 无断链。
- 后续开发者能从零启动 mock API 和移动端。

## 4. M1：本地账本闭环

### 范围

- SQLite 初始化和向前迁移。
- 内置分类种子与收入/支出树。
- 交易新增、编辑、软删除和短时撤销。
- 手动记账 Sheet、计算键盘、分类选择、日期和备注。
- 账本月份切换、日期分组、每日小计。
- 空账本、删除撤销、存储错误和非法金额。

### 交付物

- `apps/mobile/src/db/` schema、migrations、repositories。
- `packages/domain` 金额、交易、日期和分类规则。
- `packages/contracts` 对应 schema。
- repository 单测和关键组件测试。

### 验收

- 无网络时可新建、编辑和删除账单。
- 金额 `12.5` 存为 `1250`，重启后金额不变。
- 跨月、跨时区账单归入正确日期。
- 删除后 8 秒内可撤销；撤销后统计同步恢复。
- 数据库事务失败时不产生半笔账单。

### 依赖与风险

- 必须先定稿分类初始数据。
- Expo SQLite 迁移机制需在真机验证一次。

## 5. M2：分类与统计

### 范围

- 分类新增、改名、排序、归档和恢复。
- 最近使用分类、常用分类和搜索。
- 月支出/收入/结余、较上月变化。
- 每日柱状图、分类占比、日期明细和分类下钻。
- 空月份、只有收入、无分类数据状态。

### 交付物

- 分类管理页和编辑 Sheet。
- 可复用图表组件。
- 统计聚合纯函数和固定时区测试。
- 设计稿中的图表与空状态。

### 验收

- 分类归档后历史账单仍正确显示。
- 每日金额之和等于月总额。
- 分类占比四舍五入后合计 100%。
- 点击柱状图进入正确日期，返回保留滚动位置。
- 大字体与窄屏无横向溢出。

## 6. M3：语音链路

### 6.1 先做 mock 闭环

- 按住录音、计时、上滑取消、最短时长。
- 上传到 `/v1/voice/parse`，服务端返回 mock 多笔结果。
- 客户端校验、自动保存、结果卡和撤销。
- 缺金额修正、网络失败、额度耗尽和权限拒绝。

### 6.2 再接真实供应商

- ASR 适配器：录音转写、超时、错误映射。
- LLM 适配器：结构化输出、Schema 修复、最多 5 笔。
- 分类目录与别名注入。
- 固定 200 条评测集和指标报告。

### 交付物

- 语音状态机与录音组件。
- API 鉴权/额度/限流基础。
- 真实供应商环境变量和部署文档。
- 语音评测脚本或至少可重复执行的评测记录。

### 验收

- 松手到落账 P50 ≤ 3 秒、P95 ≤ 5 秒。
- 金额 ≥ 98%、类型 ≥ 95%、一级分类 ≥ 90%。
- 一句话 1–5 笔全部正确保存；6 笔被拒绝。
- 缺金额不落账；网络失败不损坏已有账本。
- 服务器不保留录音，日志不出现转写和账单正文。

### 阻塞项

- 真实 ASR 和模型密钥。
- 供应商网络可达性、计费和后端部署域名。

## 7. M4：账号与云备份（暂缓）

微信登录、微信支付和支付宝 APP 支付依赖外部主体、认证和审核。当前不把 M4 放在 M6 之前，也不把它作为免费本地首发门禁。官方核验见 [账号、会员与支付可行性](./25-account-and-payment-feasibility.md)。

### 范围

- 微信移动端授权、服务端 code 换登录态。
- 访问令牌/刷新令牌轮换和退出。
- 游客账本首份快照。
- 自动备份触发、失败重试和状态展示。
- 新设备恢复、覆盖确认和校验失败保护。
- JSON 导出/导入、CSV 导出和删除全部数据。

### 交付物

- Auth、Backup 路由和数据库迁移。
- 微信 SDK development build 配置。
- 加密备份存储和恢复原子替换。
- 备份状态组件和冲突 Sheet。

### 验收

- 游客不登录可完成全部本地操作。
- 登录前账单完整进入首份备份。
- 断网登录不破坏本地账本。
- 两边都有数据时不静默覆盖。
- 备份失败不阻塞后续记账。
- 恢复失败保留原数据库。

### 阻塞项

- 微信开放平台移动应用 AppID/AppSecret。
- PostgreSQL、对象存储、KMS 和 HTTPS 域名。
- 账号身份方案：内部 `userId`、Sign in with Apple、手机号或微信等提供方的取舍。
- 微信个人主体、类目和登录能力审核结果；若当前账号无法通过，保持暂缓。

## 8. M5：质量与内测

### 范围

- 200 条语音口语评测和三组供应商对比。
- 12–15 名目标用户、7 天封闭试用。
- iPhone 与 Android 中低端真机矩阵。
- 崩溃、性能、无障碍、动态字体和深色系统外观检查。
- Maestro 核心链路和 CI 扩展。

### 交付物

- 测试报告、缺陷清单、修复记录。
- 用户反馈摘要和 MVP 取舍记录。
- 发布候选构建。

### 验收

- P0 缺陷为 0；P1 有明确处置。
- 7 日严重崩溃率 < 0.5%。
- 首次记账完成率 ≥ 80%，语音使用率 ≥ 60%。
- 账单金额与统计抽样核对一致。

## 9. M6：商店发布

### 范围

- App 图标、启动页、商店截图和文案。
- 隐私政策、权限说明、数据删除说明、SDK 清单。
- 本地 JSON/CSV 导出与恢复。
- iOS 隐私清单和 Android 数据安全表。
- EAS 生产构建、签名、TestFlight、安卓内测。
- 灰度发布、告警和回滚方案。

### 验收

- Apple 与安卓商店审核通过。
- 生产语音网关、额度保护和密钥可用。
- 本地 JSON 导出与恢复在真实设备上成功。
- 隐私文案与实际行为一致。
- 发布后 48 小时监控无异常峰值。

## 10. 后期阶段（M7–M11）

后期主纲和原因见 [后期产品战略](./21-post-mvp-strategy.md)。本节只定义工程里程碑和退出标准。

### M7：可信的一句话

目标：完整语音结果默认自动保存，异常才修正，用户不需要为保存再点一次确认。

交付：

- 完整结果自动写入 SQLite；
- “已记好”结果卡和 8 秒整批撤销；
- 缺金额、结构异常、网络失败不落账；
- 30–50 条真人语音；
- iPhone 与 Android 真机矩阵；
- 自动入账和先确认偏好的统一状态机。

退出标准：

- 默认路径没有“确认记账”步骤；
- 8 秒内撤销后账本与统计恢复；
- 真人金额准确率 ≥ 98%；
- 松手到结构化 P95 ≤ 5 秒；
- 不产生重复或半批账单。

详细规格：[可信语音与月末回顾](./22-voice-trust-and-monthly-review.md)。

### M8：月末回顾

目标：用户月底能用一分钟理解本月消费，并愿意主动分享不含敏感金额的回顾卡。

交付：

- 月度回顾页；
- 本地确定性文案；
- 分享预览和隐私选项；
- PNG 分享卡；
- 打开、预览、分享和回流指标。

退出标准：

- 回顾数字与统计页一致；
- 默认分享不含金额、备注和商户原文；
- 双端可生成和分享；
- 无数据月份有合理空状态。

### M9：数据安全品牌

目标：把“录音用完即弃、账本本地优先、数据可带走”变成可验证的品牌承诺。

交付：

- 隐私中心；
- 录音、云端、备份和 SDK 的可读说明；
- 导出、删除和备份状态入口；
- 日志与临时文件审计；
- 对外隐私文案和商店数据声明。

退出标准：

- 文案与实现一致；
- 日志不含录音、转写、账单正文和 token；
- 删除后旧快照不会重新上传。

### M10：创始会员与付费验证

目标：验证用户愿意为什么付费，而不是先锁死长期权益。

交付：

- 19.9 元限量创始支持包；
- 12 个月 Pro 权益；
- 服务端权益、额度、订单和退款状态；
- 会员优先使用内部 `userId` + Apple 内购，恢复购买可用；
- 成本看板；
- 付费转化和退款实验。

进入条件：

- M7–M9 退出标准满足；
- D7 留存 ≥ 25%；
- 成本可被真实账单解释；
- Apple Developer 账号、付费应用协议和税务/收款信息可用；
- 本地导出与恢复可用；微信登录和安卓商户支付不是前置条件。

### M11：增长

目标：让分享和邀请带来真正形成习惯的用户。

交付：

- 双方各 30 天的激活制邀请；
- 月末小票传播；
- 应用商店关键词和商店素材；
- 公开开发日志和创始用户共创；
- 竞品 CSV 导入的独立评估。

进入条件：

- 被邀请人激活和 D7 留存可测；
- 退款、注销和异常领取可处理；
- 分享默认隐藏敏感账本信息。

## 11. 当前下一步

当前并行推进两条不冲突的工作：

1. **M7 产品切片**：在真机验证完整语音结果自动保存、结果卡撤销、失败重试和异常修正。
2. **M8 本地回顾**：在不依赖账号的前提下完成月度回顾与隐私可控分享。
3. **M5 质量验证**：录制 30–50 条真人语音，执行双端真机矩阵和 12–15 人封闭试用。

M4 微信登录与云备份进入外部依赖 backlog；Apple 账号就绪后可单独推进 iOS 内购会员，安卓支付等经营主体就绪后再启动。成本看板需在正式会员定价前接受真实账单复核。
