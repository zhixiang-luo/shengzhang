# 账单搜索规格

日期：2026-11-05
状态：`0.1.8` 已实现
上游文档：[产品需求](./01-prd.md)、[数据模型](./10-data-model.md)、[隐私优先的产品统计](./29-privacy-first-analytics.md)

## 1. 目标

搜索解决的是“我记得有一笔，但忘记在哪一天、哪个分类”的找回问题。首版必须离线、即时，并且不把账单正文发送到服务端。

入口固定在账本页右上角。未输入条件时直接展示最近账单，而不是空白页。

## 2. 搜索条件

支持以下条件，全部使用 AND 组合：

| 条件 | 规则 |
| --- | --- |
| 关键词 | 不区分大小写，匹配备注、一级分类名和二级分类名；最多保留 80 个字符 |
| 收支类型 | `全部`、`支出`、`收入` |
| 分类 | 可选择任意一级或二级分类；选择一级分类时只匹配直接挂在该分类下的账单 |
| 开始日期 | 点击后通过月历选择，保存为 `YYYY-MM-DD`，按设备本地自然日比较 |
| 结束日期 | 点击后通过月历选择，保存为 `YYYY-MM-DD`，按设备本地自然日比较 |
| 最低金额 | 元字符串，经 `parseYuanToCents` 转为整数分 |
| 最高金额 | 元字符串，经 `parseYuanToCents` 转为整数分 |

以下输入必须被拒绝并显示中文提示：

- 开始日期晚于结束日期；
- 日期不存在，例如 `2026-02-30`；
- 金额不是合法十进制金额；
- 最低金额大于最高金额；
- 未知收支类型。

条件有误时不展示可能误导用户的结果；清除条件后恢复最近账单。

## 3. 数据流

```text
账本右上角搜索
  -> listAllTransactions(db)
  -> listCategories(db, includeArchived=true)
  -> normalizeLedgerSearchFilters(draft)
  -> matchesLedgerSearch(entry, filters, categoryById)
  -> 点击结果打开 /entry?id=<transactionId>
```

约束：

- 账单和分类均从本机 SQLite 读取，网络断开不影响搜索。
- 只读取 `deleted_at IS NULL` 的账单。
- 分类使用稳定 ID，不把展示名称当外键。
- 归档分类仍可显示历史账单；筛选器只展示当前可用分类。
- 搜索不创建副本、不修改账单，也不更新备份状态。

## 4. 页面行为

- 顶部提供 44×44 返回按钮和标题“搜索账单”。
- 默认显示“最近账单”，结果按 `occurredAt`、`createdAt` 倒序。
- 关键词输入实时筛选；类型和筛选条件变化后立即重算。
- 筛选面板展示一级、二级分类、日期范围和金额范围。
- 日期范围不提供手工文本输入：点击开始或结束字段复用现有 `DateTimePickerSheet`，以 `mode="date"` 隐藏小时/分钟和“现在”，只返回本地自然日。
- 空日期字段打开时默认定位到当前日期；确认后写回 `YYYY-MM-DD`，取消不改变原条件；已选字段可单独清除。
- 搜索框固定高度并统一使用零垂直内边距、固定行高和平台垂直居中；最低/最高金额输入使用相同规则，确保占位词、用户输入和数字都在框内居中。
- “筛选 N”显示当前有效条件数，关键词也算一项。
- 结果标题显示结果笔数；无结果时提示缩短关键词或放宽范围。
- 结果行展示分类图标、备注或分类名、分类路径、日期时间和金额。
- 点击结果进入既有账单编辑页；返回后搜索页重新读取本机数据。

## 5. 匿名统计

新增两个固定事件，不包含搜索词、金额、日期、分类名或账单正文：

| 事件 | 触发时机 | 属性 |
| --- | --- | --- |
| `ledger_search_opened` | 搜索页获得焦点 | 平台、App 版本 |
| `ledger_search_applied` | 用户提交搜索或应用筛选 | 平台、App 版本、有效条件数量 |

条件数量上限为 7。统计只用于判断搜索是否被使用，以及用户通常组合多少条件。

## 6. 性能与边界

- 首版直接在设备内存中过滤当前本机账单。个人账本通常远低于 5000 笔。
- 单次打开只读取一次全量有效账单和分类；输入时不在 UI 线程重建 SQLite 查询。
- 5000 笔账单下仍需在真机验证输入响应、列表滚动和筛选面板布局。
- 首版不支持保存搜索、全文索引、模糊纠错、语音搜索或跨设备搜索。
- 搜索属于本地增强能力，不依赖会员、登录、云备份或支付。
