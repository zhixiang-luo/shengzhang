# 云端直接识别、原页面浮层与快捷入口

2026-11-13 用户已批准开发；同日 0.3.3 真机反馈修订删除边缘按钮和设置页“添加快捷动作”，以 [42号记录](./42-quick-accounting-device-feedback.md) 为准。本轮决定取代 0.3.1 的“先本地再云端、回主应用确认、保存后八秒撤销”路线；旧实现及验收结果保留在 38 号记录。

## 已确认的体验

用户在微信或支付宝付款详情主动触发声账动作，服务先隐藏自身入口并截图，再在原页面上方显示紧凑确认卡。云端直接读取图片，结果填入金额、商品或商户、交易时间及分类；不先运行本地 OCR，不由本地交易状态决定是否调用云端。无商品依据时只显示商户，金额未知保留空值，时间未知标明默认当前时间。

点击“确定收好了”即写入现有 SQLite 账本，成功后简短提示并关闭浮层。快捷记账不再显示第二个“收好”、撤销按钮或八秒等待；失败保留编辑内容并允许重试，重复点击按 captureId 幂等。语音记账既有撤销行为不变。

Android 使用已授权无障碍服务的 TYPE_ACCESSIBILITY_OVERLAY；不申请 SYSTEM_ALERT_WINDOW，不采用透明主 Activity 模拟确认卡。截图分享仍可在应用内确认，但同样云端直接识别、一次保存。分享动作本身不需要无障碍；原页面浮层需要无障碍服务已连接。

## 执行边界

- 主应用仍为 Expo SDK 58 / RN 0.88，遵循 CNG，不手写 apps/mobile/android。
- 原生浮层、网络调用与同账本读写放在 packages/screen-capture。配置由已完成迁移的应用传入，数据库路径取 Expo SQLite 的真实路径；原生不得自行建立另一套账本或改旧迁移。
- 原生打开库前检查 schema 版本 3，启用外键及 busy timeout。校验金额正整数分、有效同收支分类、时间及 captureId；一次数据库事务写账并标记备份 pending。
- 云端作为启用快捷记账后的默认方式。首次启用明确告知图片及供应商处理，同意后不逐次确认；明确关闭的用户不静默重新开启。密钥仅在服务端。
- 手机上传当前图、分类及请求上下文，不传历史账本。无网络、配额耗尽、超时、截图安全限制均明确提示，不伪造零元或悄悄降级为不可靠本地结果。
- 默认目标供应商是用户提出的千问官方 qwen3-vl-plus；需核实实际官方 API、密钥和处理条款后启用，未具备凭证不能宣称已经切换。不得把硅基流动密钥发到其他供应商地址。
- 微信失败先排查活动窗口与采集阶段；无障碍节点缺失不等于无法截图。只观察窗口包名以识别主动触发的来源，不在后台遍历页面文字；只在点击时截图。
- 银行未加入自动采集白名单，安全窗口不可绕过；单张主动分享仍可尝试。

## 快捷入口

设置页只引导开启无障碍和添加标准 Quick Settings Tile；系统确认添加后打勾，移除后恢复，未知状态不假勾。删除屏幕边缘按钮及升级前旧开关，删除“添加快捷动作”按钮，仅用简短说明提示部分手机可去系统设置绑定背部轻点、侧键等。底层系统无障碍按钮与独立 Activity 动作仍可供兼容系统调用，共用一次采集逻辑。桌面/手势调用用独立轻量入口立即结束后再采集下面的页面，不打开声账主界面。

App 提供可调用动作；双击后盖、侧键、双击屏幕等绑定由系统/厂商设置决定。不能承诺所有 Android 机型任意绑定，更不能把双击亮屏等同于亮屏付款页上调用第三方动作。iOS 本轮只调研，不实现，且不能等同承诺跨应用无障碍浮层。

## 验证与发布

先运行针对性的红绿回归、全仓 typecheck/lint/test、API build、双端 export，再以 EAS 编译原生 APK 并核对签名和权限。需要新 native runtime，不能只 OTA。无连接设备时仅报告构建/包级结果，不冒充真机通过。

依然先交付用户安装测试，官网、CDN、更新策略保持 0.2.1。供应商切换、真实页面精度和各厂商手势支持按实际证据记录。
