# 架构决策记录

ADR-001 至 ADR-006 的基线定义在 [技术架构](./09-technical-architecture.md#11-架构决策记录)，本文件不重复。以下只记录跨产品、工程和文档流程的新增决策。新决策追加而不覆盖历史。

## 已确定

| ID | 决策 | 理由 | 影响 |
| --- | --- | --- | --- |
| ADR-007 | pnpm workspace 单仓 | 共享契约、统一 CI、方便其他 AI 接手 | 需要正确配置 Expo monorepo |
| ADR-008 | `AGENTS.md` 为唯一 AI 规则源 | 避免 `magent.md`、`CLAUDE.md` 等重复冲突 | 详细规格放 docs，不写进规则文件 |
| ADR-009 | 原型用 HTML/CSS/JS 手工编码 | 状态流转可点击、易评审、零构建 | 原型不是生产代码 |
| ADR-010 | 不引入 Redis | MVP 单服务、低并发，PostgreSQL 原子计数足够 | 扩容后再评估 |
| ADR-011 | 先用 Expo Go/EAS，后装原生工具链 | 避免早期下载数十 GB 工具；现有代码可直接启动 | 原生微信 SDK 联调前仍需 Xcode/Android Studio |
| ADR-012 | 以仓库文档而非聊天摘要作为事实 | 支持多 AI 接力与审计 | 每阶段必须更新 HANDOFF 和追踪矩阵 |
| ADR-013 | 完整语音结果默认自动入账，异常才确认 | “松手即入账”是产品主承诺；二次确认会抹平语音优势 | 结果卡改为“已记好”，8 秒撤销；缺金额和异常保留修正路径 |
| ADR-014 | 后期按可信语音、月末回顾、数据安全三轴推进 | 模型本身容易同质化，长期价值来自准确性、习惯和信任 | 会员与分享不得早于三项基础能力 |
| ADR-015 | 19.9 元只做限量创始支持包，不做终身无限 AI | 推理和存储是持续成本，低价终身会形成无法关闭的负债 | 先验证付费，再决定年费和买断版 |
| ADR-016 | 分享默认隐藏金额、备注和商户原文 | 财务数据具有高敏感性，分享不能以隐私换增长 | 需要预览、主动选择和最小化埋点 |
| ADR-017 | 账号身份、会员权益与支付渠道解耦 | 微信登录只是身份提供方，不能成为会员的前置条件；不同平台支付规则不同 | 内部使用 `userId + entitlement`，登录和支付分别做适配器 |
| ADR-018 | 免费本地首发不依赖微信登录、云备份和支付 | 外部主体与审核不应阻塞核心产品验证 | PRD、M4 和发布门禁调整为后续能力 |
| ADR-019 | iOS 数字会员优先使用 Apple 内购 | 个人可申请 Apple Developer；iOS 数字功能按规则必须用 IAP | 微信/支付宝 APP 支付等经营主体就绪后再评估 |
| ADR-020 | 分类同级排序使用整行长按拖拽 | 直接调整位置比连续点击上移/下移更符合用户心智，并可在一次拖拽后提交完整顺序 | 使用兼容 React Native 0.88 Fabric 的 `react-native-reorderable-list`；整行保留无障碍上移/下移动作 |
| ADR-021 | 项目采用 MIT License 开源 | 便于用户查看真实实现、作为个人作品展示，并降低开发者复现和参与门槛 | 代码可用于闭源商业项目；品牌、用户数据和云端密钥不随代码授权 |
