# 付款页快捷记账设计

## 1. 状态与目标

- 状态：已获产品方向批准，进入首版实现
- 目标版本：`0.3.0`
- 首发平台：Android 11+
- 兼容方向：iOS 使用用户主动运行的快捷指令，不走静默读屏

用户付款完成后，通过控制中心的“声账记账”磁贴触发一次读取。应用优先获取当前付款结果页的文字节点；文字不足时获取一次临时截图并在本机 OCR。识别结果先进入可编辑确认卡，用户确认后才写入 SQLite。原始截图不上传、不进相册，也不进入备份。

## 2. 产品边界

首版只支持：

- 微信支付和支付宝的常见付款成功页；
- 单笔支出；
- Android 11 及以上；
- 用户主动点击磁贴触发；
- 金额、时间、商户/内容、分类可修改；
- 保存后同一浮层内展示 8 秒撤销。

首版不支持：

- 后台持续监听屏幕；
- 自动识别付款并直接落账；
- 通知监听、读取剪贴板或支付平台接口；
- 银行账单批量导入；
- 退款、转账、分账和多笔识别；
- 保证所有支付 App、所有页面都能读取。

## 3. 平台策略

### Android 11+

1. 用户手动开启无障碍服务，并把“声账记账”添加到快捷设置。
2. 点击磁贴后，服务收起快捷设置并等待当前付款页重新成为前景窗口。
3. 只读取白名单应用中的无障碍文本节点。
4. 页面文本不足时，通过无障碍服务的截图能力获取一次临时截图，并使用端侧中文 OCR。
5. 结构化草稿写入应用私有待处理区，随后通过 deep link 打开声账确认页。
6. 用户在确认页保存或取消后，删除临时截图与原始文本。

### iOS

iOS 公开 API 不允许普通应用静默读取其他 App 的屏幕。兼容路线是让用户创建快捷指令：执行系统“截屏”，再把图片交给声账 App Intent。首版先完成统一确认页与本地结构化能力；iOS App Intent 在 Android 真机闭环通过后单独接入，避免让未验证的原生代码阻断 Android 验收。

## 4. 数据流

```text
快捷磁贴
  -> 等待付款页回到前台
  -> 读取无障碍文本
  -> 文本足够：直接解析
  -> 文本不足：临时截图 + 本地 OCR
  -> 规范化金额/时间/商户/分类
  -> 确认浮层
  -> 用户修改
  -> 单事务写入 SQLite
  -> 同一浮层显示撤销
```

原始 OCR 文本只保存在内存。跨进程交接仅使用应用私有目录中的短期草稿；截图最长保留 5 分钟，并在确认、取消、保存或下次启动清理时删除。

## 5. 确认浮层

页面背景使用临时付款页截图并降低视觉权重；截图不可用时使用纯色背景。底部为主确认卡：

- 标题：“识别到一笔账单”
- 金额：最大视觉层级，可点击打开现有金额键盘；
- 收支类型：首版默认支出，允许切换；
- 分类：使用现有两级分类选择与创建能力；
- 时间：复用现有日期时间选择器；
- 商户/内容：映射到现有 `note` 字段，长度最多 40 字；
- 操作：“取消”和“记好这笔”。

保存成功后不弹第二个确认框。同一卡片切换为“已记好”，展示金额和“撤销”按钮，8 秒后回到账本。

## 6. 识别规则

核心结构化函数放在 `packages/domain`，不依赖 React Native：

- 全角数字、`¥/￥/元`、千分位和中文金额统一规范化；
- `实付/支付金额/付款成功/合计` 的候选优先级高于 `原价/优惠/余额`；
- 手机号、订单号、卡号尾号、余额不作为金额候选；
- 金额输出统一为整数分；
- 页面含有付款成功语义且只有一个可信金额时，置信度才为 `high`；
- 存在多个金额、无法确认实付金额或页面不像付款结果页时，进入低置信度修正态；
- 时间优先解析页面文本，否则使用设备当前时间并保持可编辑；
- 商户/内容取收款方、商户、付款给、商品等高优先级文本，无法确定时留空；
- 分类只做保守推荐，无法匹配时落到“其他”；
- 同一 `captureId` 只能创建一条账单，重复确认不得重复入账；
- 保存前用金额、时间窗口和备注做近似重复提示，但不阻止用户最终确认。

## 7. 数据模型

`TransactionSource` 扩展为：

```ts
type TransactionSource = 'voice' | 'manual' | 'screen';
```

SQLite 通过迁移 v3 重建 `transactions` 表，把 `source` 约束扩展为三者兼容。确认页生成的 `captureId` 直接作为新账单主键，从数据库层保证幂等。页面的原始文本、截图路径和 OCR 正文不进入账单、JSON 备份或 CSV。

备份和 CSV 同步支持 `screen`，显示为“屏幕识别”。

## 8. 原生模块边界

新增本地 Expo 模块 `packages/screen-capture`：

- TypeScript 包装：权限状态、添加磁贴、读取/清除待处理草稿、OCR；
- Android `BillCaptureTileService`：快捷设置入口；
- Android `BillCaptureAccessibilityService`：仅在触发后读取窗口、截图和打开确认页；
- Android `PendingCaptureStore`：根目录私有的短期 JSON 与截图；
- Android OCR：ML Kit 中文文字识别，端侧执行；
- iOS：首版返回明确的“使用快捷指令”能力状态，不伪装不支持的系统能力。

该模块会产生新的原生依赖，必须重新构建 APK，不能通过 Expo Go 或 OTA 获得。

## 9. 隐私与失败处理

- 首次开启前展示用途、触发方式和数据保留说明；
- 不读取白名单外应用；
- 不在用户未触发时读取窗口；
- 不保存完整截图到相册或长期目录；
- 日志不记录金额、商户、OCR 正文或截图路径；
- 无权限：跳转设置并说明；
- 非付款页/白名单外：返回确认页并预填“请手动补充”；
- 安全页面无法截图：仍尝试文本，失败后手动填写；
- ML Kit 不可用：继续使用文本结果或手动填写；
- 后台进程被杀、草稿超过 5 分钟：丢弃草稿并要求重新触发。

## 10. 验收标准

- 在至少一台 Android 11+ 真机上能添加磁贴、触发、读取文本并打开确认页；
- 用微信/支付宝模拟付款页样本可识别金额、时间和商户；
- 无障碍文本缺失时能完成 OCR 兜底；
- 所有字段可修改，保存后账本出现来源为“屏幕识别”的账单；
- 同一草稿重复保存只生成一笔账单；
- 保存后同一页面可撤销；
- 取消、保存、超时后临时截图被删除；
- 旧版 JSON 备份仍可导入，新版含 `screen` 的备份可往返；
- `pnpm typecheck`、`pnpm lint`、`pnpm test`、Android export 通过；
- 新 APK 能安装并与旧版 SQLite 数据兼容。
