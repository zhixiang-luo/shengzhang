# 开源项目运营边界

日期：2026-10-21
状态：公开仓库前的安全与运营基线

## 1. 代码授权不等于线上服务授权

声账源代码使用 MIT License。任何人都可以按照许可证使用、修改和分发代码，但这不代表获得以下授权：

- 使用“声账”名称、Logo、小猪角色或官方视觉冒充官方版本；
- 使用项目维护者的 AI 供应商账号、云服务器、数据库或对象存储；
- 无限调用维护者提供的线上语音接口；
- 获得官方支持、可用性承诺或数据安全背书。

品牌边界见根目录 `TRADEMARK.md`。自部署者应使用自己的环境变量、供应商账号和额度。

## 2. 密钥与费用边界

- DeepSeek、火山引擎、SiliconFlow、微信、阿里云和对象存储密钥只允许存在于服务端环境变量或密钥管理系统中。
- 移动端只能持有公开 API 地址，不得打包任何供应商密钥。
- GitHub Actions 不保存生产供应商密钥；当前 CI 只执行类型检查、Lint 和测试。
- 开源仓库不会让第三方取得维护者的供应商密钥，但公网 API 地址本身可以被调用。
- 因此，线上 API 必须独立实施安装额度、IP 限流、异常行为限制、供应商预算告警和快速停用开关。
- 如果攻击者绕过客户端直接调用公网 API，风险是消耗维护者的服务额度，而不是读取仓库中的 Key。

## 3. 公开前安全基线

- 全量 Git 历史不得包含 `.env`、私钥、签名文件、Token、真实账单或录音。
- `.env.example` 只能包含空值和明确占位符。
- GitHub Actions 默认权限设为只读，工作流按任务单独提权。
- 开启 Dependabot、Secret Scanning、Private Vulnerability Reporting 和依赖安全告警。
- 保护 `main` 分支，禁止强制推送和分支删除，并要求 CI 通过。
- Pull Request 不自动获得 Secrets；来自 Fork 的工作流不得接触生产环境。
- GitHub Release 可以分发 APK，但不把 APK、签名文件或构建缓存提交到 Git。

## 4. 公开后的维护规则

- 安全漏洞通过 `SECURITY.md` 指定的私密渠道处理，不在公开 Issue 中披露用户数据。
- 依赖更新优先通过 Dependabot 小批量合并，升级后必须重新执行测试。
- 发布版本使用语义化版本号和 Release Notes，明确数据迁移和兼容性影响。
- 不在 Issue 回复中索取真实账单、录音、手机号或身份信息。
- 线上服务条款、隐私政策和 API 额度策略与开源许可证分开表达。

## 5. 当前判断

以个人履历、用户信任和独立开发者品牌为目标，公开源码的收益大于隐藏代码的收益。项目真正的壁垒是产品体验、品牌、用户反馈、模型评测和持续迭代，而不是仓库可见性。
