# 改进与反馈

## 1. 目标

为声账提供一个不需要登录、不会暴露账本内容的站内反馈入口，让用户可以用较低成本报告问题或提出建议，同时让独立开发者获得足够的上下文进行定位和回复。

首版不建设完整客服工单系统，只完成：

`设置 → 改进与反馈 → 填写并提交 → 私有收件箱 → 每日统计`

## 2. 产品原则

- 匿名提交，联系方式选填。
- 只要求用户描述问题，不要求提供账单、录音或转写。
- 自动诊断信息必须最小化，并允许用户关闭。
- 反馈正文属于用户内容，不进入匿名产品统计。
- 提交失败必须保留已填写内容，并允许原样重试。
- 网络重试不能产生重复反馈。

## 3. 页面与交互

### 3.1 设置入口

设置页新增“帮助与反馈”分组，在该分组中提供：

`改进与反馈 / 问题或建议`

入口位于“应用更新”之前，避免用户必须先经过版本信息才能表达问题。

### 3.2 反馈页

页面标题为“改进与反馈”，首屏文案说明反馈会直接交给独立开发者。

字段：

| 字段 | 规则 |
| --- | --- |
| 反馈类型 | 必选；建议、使用问题、语音、记账、数据安全、其他 |
| 详细描述 | 必填；去除首尾空白后 10–1000 字 |
| 联系方式 | 选填；最多 200 字，可填写邮箱、微信或手机号 |
| 诊断信息 | 默认开启；可关闭 |

诊断信息只允许包含：

- App 版本
- 平台与系统版本
- 系统语言
- 当前页面
- 可选错误码
- 可选请求 ID

页面明确说明不会自动附带金额、分类、备注、录音和语音转写。

提交状态：

- idle：显示“发送反馈”
- submitting：按钮显示“正在发送”，禁止重复提交
- success：显示反馈编号和“再提一条”
- error：保留输入内容，显示“没有发送成功”和重试说明

### 3.3 成功反馈

成功后展示：

> 收到了，谢谢你帮声账变好。

同时显示反馈编号，例如 `FB-20261107-A1B2C3`。没有联系方式时明确提示无法逐一回复；有联系方式时提示会在需要时联系。

## 4. 数据契约

`POST /v1/feedback`

```json
{
  "clientFeedbackId": "uuid",
  "installationId": "local-installation-id",
  "type": "voice",
  "message": "语音完成后，昨天的时间显示不对",
  "contact": "可选",
  "diagnostics": {
    "appVersion": "0.2.1",
    "platform": "android",
    "osVersion": "15",
    "locale": "zh-CN",
    "currentRoute": "feedback",
    "errorCode": null,
    "requestId": null
  }
}
```

成功响应 `202`：

```json
{
  "referenceCode": "FB-20261107-A1B2C3",
  "createdAt": "2026-11-07T14:30:00.000Z"
}
```

同一 `clientFeedbackId` 重试必须返回同一反馈结果，不重复保存。

## 5. 服务端存储

- 目录由 `FEEDBACK_DATA_DIR` 配置，生产指向 `/opt/shengzhang/shared/reports/.feedback`；该目录归服务账号所有并限制为 `0700`，不随公开报告发布。
- 按北京时间日期分目录，每条反馈保存为独立 JSON 文件。
- 文件权限 `0600`，目录权限 `0700`。
- 原始安装 ID 只保存加盐 SHA-256，不保存明文。
- 文件名使用 `clientFeedbackId` 的 SHA-256，保证幂等。
- 默认保留 180 天；服务器每日执行 `prune-feedback.sh`，按北京时间删除更早的反馈目录。

## 6. 限流与防滥用

- 单 IP 每 10 分钟最多 5 条。
- 单 IP 每天最多 30 条。
- 全局每天最多 500 条。
- 请求体上限 16 KiB。
- 所有边界使用 Zod 严格校验。

## 7. 运营与隐私

- 每日运营简报只输出反馈总数和类型分布，不输出正文和联系方式。
- 开发者通过服务器私有命令查看具体反馈。
- 反馈正文和联系方式不写入普通应用日志。
- 联系方式仅在用户主动填写时保存。
- 反馈提交成功率作为产品事件统计，只记录类型和失败原因，不记录正文。

## 8. 首版不包含

- 截图或文件附件
- 用户可见的工单状态和站内回复
- 自动邮件通知
- 反馈投票和公开看板
- GitHub 账号前置登录

## 9. 验收标准

- 设置页可进入反馈页，返回不丢失设置页状态。
- 未选择类型、描述少于 10 字或超过 1000 字时不能提交。
- 匿名用户可提交，联系方式可空。
- 关闭诊断信息后，服务端不收到诊断对象内容。
- 网络中失败后输入内容不丢失，重试不产生重复记录。
- API 拒绝超长、未知字段和未知反馈类型。
- 服务端不保存明文安装 ID，普通日志不含反馈正文和联系方式。
- 日报只出现反馈数量和类型分布。
- 类型检查、Lint、移动端/API 测试和相关构建通过。

## 10. 生产运维入口

```bash
# 查看某日反馈数量与类型分布
/opt/shengzhang/shared/reports/bin/feedback-report.sh --date=YYYY-MM-DD

# 开发者查看某日私有反馈明细
/opt/shengzhang/shared/reports/bin/feedback-report.sh --date=YYYY-MM-DD --format=jsonl

# 手动清理指定日期之前的反馈
/opt/shengzhang/shared/reports/bin/feedback-report.sh --prune-before=YYYY-MM-DD
```

服务器每日北京时间 00:35 自动执行 `prune-feedback.sh`，计算 180 天前的日期并清理旧目录。反馈明细命令只允许在服务器私有环境中执行，输出不得转发到公开日志、Issue 或聊天。
