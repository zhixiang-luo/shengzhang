# 声账 MVP 产品需求文档

## 1. 文档信息

- 产品名称：声账
- 副标题：一句话语音记账
- 品牌主张：说一句，就记好。
- 版本：MVP 1.0
- 平台：iOS、Android
- 市场：中国内地
- 语言与币种：简体中文、人民币
- 产品阶段：可上架 MVP

## 2. 产品定位

声账面向 18–35 岁学生和年轻职场人，解决“付款后不想打开复杂记账应用”的问题。用户按住语音按钮说一句自然语言，系统识别金额、收支类型、分类、日期和备注，自动生成账单，并允许撤销或修改。

产品不是全功能财务管理系统。首版只做个人日常收支记录，以最低录入成本、清爽视觉和可信的统计结果建立差异。

### 核心用户任务

> 我刚付完钱，希望几秒内把这一笔或几笔记下来，之后能看懂这个月钱花在了哪里。

## 3. 产品原则

1. 语音是主路径，手动记账是稳定兜底。
2. 首次使用不强制登录，游客可以直接记第一笔。
3. 一屏只保留一个主行动，不制造多层入口。
4. 自动入账必须有明确结果反馈和可撤销能力。
5. 统计先保证准确和可读，不堆叠预测、排行和复杂指标。
6. 界面亲切但不幼稚，小猪只作为克制的品牌角色。

## 4. 目标与成功指标

### 用户目标

- 新用户在 30 秒内完成第一笔记账。
- 用户从打开 App 到语音入账完成不超过 5 秒。
- 用户能在一个月内清楚看到每日支出和分类构成。

### 产品指标

| 指标 | MVP 目标 |
| --- | --- |
| 首次记账完成率 | ≥ 80% |
| 首次会话语音使用率 | ≥ 60% |
| 语音松手至入账 P50 | ≤ 3 秒 |
| 语音松手至入账 P95 | ≤ 5 秒 |
| 金额识别准确率 | ≥ 98% |
| 收支类型识别准确率 | ≥ 95% |
| 一级分类首选准确率 | ≥ 90% |
| 第 7 日留存 | ≥ 25% |
| 7 日内严重崩溃率 | < 0.5% |

行为事件只记录匿名、最小化事件，不上传账单正文、分类明细或录音。

## 5. 用户与场景

### 主要用户

- 有日常消费但不愿维护复杂表格的学生和年轻职场人。
- 曾安装记账应用，但因录入步骤多、分类难找、界面杂乱而放弃的人。
- 希望偶尔回看月度消费，而不是做专业财务分析的人。

### 高频场景

- 午饭、咖啡、打车后立即记一笔。
- 一次说清多笔：“早饭 12，打车 30”。
- 第二天补记：“昨天晚饭 68”。
- 发工资、收红包、退款时记录收入。
- 月底查看每日支出、分类占比和最大支出日。

## 6. 范围与优先级

### P0：首版必须完成

- 游客模式、首次引导、语音权限说明。
- 按住录音、上滑取消、网络识别和自动入账。
- 一句话 1–5 笔、支出/收入、中文金额、相对日期、分类和备注。
- 自动入账结果卡、逐笔编辑、8 秒整批撤销。
- 缺金额修正、网络失败、额度耗尽、权限拒绝等关键异常。
- 手动记账、编辑、删除、月份账本和日期分组。
- 两级分类、内置分类、自定义分类、排序和归档。
- 月统计、每日图表、分类占比、日期明细。
- 微信移动端一键登录、游客账本合并、自动云备份和手动恢复。
- JSON 备份导入、CSV 导出、删除全部数据。
- 隐私说明、权限说明、账本离线可用。

### P1：首版之后

- 实时多端同步与冲突合并。
- 预算、年度报表、桌面小组件。
- 周期记账、账单搜索、深色模式。
- 微信登录账号注销和更多恢复版本。

### P2：暂不承诺

- 多账本、家庭共享、多人分账。
- 资产、负债、转账、报销和投资。
- 银行或支付平台账单自动导入。
- 截图 OCR、自动记账、发票识别。
- 会员、广告、社交和游戏化养成。

## 7. 功能需求

### 7.1 首次启动

- 直接进入游客空账本，不显示强制登录。
- 用一张轻量说明介绍“按住说话即可记账”。
- 首次点击语音时解释麦克风和云端识别，用户拒绝后仍可手动记账。

### 7.2 语音记账

- 账本底部中央按钮本身就是录音控件：按下立即进入录音，松手直接提交；不先打开中间面板，也不要求再点击“语音入账”。
- 按住按钮开始录音，松手提交；上滑超过阈值取消。
- 单次最长 30 秒，一句话最多生成 5 笔。
- 默认每天 20 次语音解析额度，由服务端远程配置；每次解析无论生成几笔计一次。
- 识别成功后自动保存，并展示“已记好”结果卡。
- 结果卡支持逐笔编辑和 8 秒整批撤销。
- 金额缺失时不保存整批，打开修正面板补齐；分类不确定时保存最优结果并允许修改。
- 无网络、额度耗尽或服务异常时提供明确原因、重试和手动记账入口。
- 设置中可切换“自动入账”和“每次先确认”，默认自动入账。

### 7.3 手动记账与账本

- 手动记一笔只使用单页面板，支持支出/收入、金额、分类、时间、备注。
- 数字键盘支持基础四则运算，金额按分存储。
- 账本默认显示当前月，按日期分组展示每日收支小计和账单。
- 账单可编辑、删除；删除需即时反馈并提供短时撤销。

### 7.4 分类

- 支出和收入分别维护分类。
- 两级分类，内置分类开箱即用。
- 用户可新增、改名、排序和隐藏分类；被账单引用后只能归档。
- 语音有独立别名映射，别名不直接增加用户界面复杂度。

### 7.5 统计

- 当前月为默认周期，可前后切换月份。
- 展示支出、收入、结余和较上月变化。
- 每日支出柱状图可点击查看当天明细。
- 分类占比展示金额、笔数和百分比，可下钻到二级分类。
- 展示日均支出和本月最大支出日。

### 7.6 账号与云备份

- 游客完成第一笔账单后，轻提示“开启云备份”，可永久跳过。
- 首版仅支持微信移动端一键登录，不做扫码或 Web 登录。
- 登录后将游客账本合并为首份云端备份。
- 本地账本继续作为主数据源，后续变化自动备份，失败时保留待重试状态。
- 云备份用于备份和换机恢复，不承诺实时多端同步。
- 新设备登录且本地为空时可恢复最近备份；两边都有数据时必须由用户明确选择。
- 退出登录不删除本机账本，只停止后续备份。

### 7.7 数据管理

- 导出完整 JSON 备份，包含版本号和数据校验信息。
- 导出 CSV 供用户自行查看。
- 恢复前说明覆盖或合并规则，并二次确认。
- 删除全部数据需要二次确认，明确本机与云端是否同时删除。

## 8. 发布约束

- 需要 Apple Developer、安卓发布账号、微信开放平台移动应用资质。
- 语音网关服务需要域名、HTTPS、隐私政策和必要备案。
- 上线前完成商标与商店名称复核。
- iOS 与 Android 同步发布；商店构建、隐私清单和权限文案必须一致。

## 9. MVP 完成定义

用户可在两台平台真机上完成“游客记第一笔 → 一句话多笔 → 微信登录 → 云备份 → 新设备恢复 → 查看月度统计”的完整流程，且无阻断性错误、无账目丢失、无录音或账单正文进入日志。
