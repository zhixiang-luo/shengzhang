# 语音记账规格

## 1. 体验目标

用户一次按压、一句话、一次松手即可完成账单。语音流程的速度优先级高于展示信息量，任何额外确认都必须有充分理由。

## 2. 输入规则

- 入口：底部中央记账按钮直接开始录音，不在进入录音前增加面板或二次确认。
- 交互：按住底部中央按钮开始录音；上滑超过 36pt 进入取消态，向下回到 16pt 内可恢复继续说话；向右滑超过 48pt 进入手动记账态并在浮层点亮提示；正常松手立即提交。
- 空语音：松手时实时文字仍为空，视为用户放弃本次输入，直接关闭浮层，不调用结构化接口，也不提示错误。
- 实时字幕：录音期间通过 WebSocket 持续发送 16kHz PCM，网关转发到火山双向流式 ASR；火山每 100–200ms 左右返回累计文字，通常在首个语音包后约 1 秒内出现字幕。松手后把最终累计文字提交给大模型，实时文字为空则视为取消。
- 时长：最短 300ms，最长 30 秒；接近上限 5 秒时提示。
- 格式：16kHz 单声道 AAC/M4A，客户端压缩后上传。
- 网络：语音识别必须联网；离线时直接提示并提供手动记账。
- 额度：默认每安装每天 20 次解析，单次最多 5 笔，服务端可远程调整。
- 语言：普通话为主，兼容常见口语、中文数字和省市口音。

## 3. 状态

| 状态 | 界面 | 可用操作 |
| --- | --- | --- |
| idle | 中心语音按钮 | 按住 |
| recording | 浮层、实时字幕、上滑取消提示 | 松手提交、上滑取消、右滑手动 |
| uploading | 轻量处理中 | 不可重复提交 |
| parsing | “正在整理账单” | 可取消，取消不落账 |
| saving | 正在写入账本 | 不重复提交 |
| saved | “已记好”结果卡 | 8 秒整批撤销、关闭 |
| needs_amount | 修正面板 | 补金额、保存、放弃 |
| failed | 人话错误信息 | 重试、手动记账 |

## 4. 解析字段

每笔账单至少产出：

- `type`: expense / income
- `amountMinor`: 整数，单位分
- `occurredAt`: ISO 8601 时间
- `categoryPath`: 一级/二级分类名称
- `note`: 可选备注

若信息不足，字段为空并返回 `unresolvedFields`。客户端不得猜测缺失金额。

## 5. 自然语言规则

### 金额

必须支持：

- 阿拉伯数字：`12`、`12.5`、`12块5`
- 中文数字：`十二`、`二十五`、`一百二`
- 口语单位：`块`、`元`、`毛`、`角`
- 计算表达：`三个人一共 90` 可解析为 90，不自动均摊
- 多笔分隔：逗号、句号、“然后”、“还有”

无法唯一确定金额时进入修正态，例如“花了差不多几十”。

### 日期

- 未说明日期：当前本地时间。
- 完全未说明日期或时刻时，不采用模型生成的 `occurredAt`，服务端统一写入本次解析时的当前时间。
- `今天/刚才/刚刚`：当前日期。
- `昨天/前天`：相对当前日期。
- `周一/上周三`：按当前周一起算，并受时区影响。
- `10月5号`：优先当年；若晚于当前日期且语境为过去账单，使用上一年。

### 收支类型

- 明确收入动词：发工资、收到、到账、退款、报销。
- 明确支出动词：买了、花了、付了、打车、吃饭。
- 无法判断时默认支出。
- “发红包 200”默认为支出，“收到红包 200”默认为收入。

### 多笔

一句话允许多个金额和消费对象。每笔独立分类、金额和备注，按出现顺序保存。

超过 5 笔不保存，提示拆分为两次语音。

## 6. 自动入账与撤销

- 所有解析字段完整且金额合法时，按同一 `voiceRequestId` 以单个 SQLite 事务自动写入账本。
- 默认路径不展示“要记这几笔吗”式的确认按钮；用户松手后直接完成保存。
- 保存成功后展示“已记好”结果卡，包含每笔摘要、总金额和 8 秒整批撤销。
- 撤销按批次软删除本轮生成且未被单独修改的账单；结果卡关闭后仍可从账本编辑或删除。
- 金额缺失时不写入任何一笔，必须补齐后才允许保存。
- 金额缺失、结构异常或用户主动开启“每次先确认”时，才展示修正或确认状态。
- 用户主动选择“每次先确认”属于个人偏好，不改变默认自动入账策略。

## 7. 服务端接口

```text
POST /v1/voice/transcribe
Content-Type: multipart/form-data

audio
installationId

Response:
{
  "transcript": "午饭25，打车18",
  "latencyMs": 420
}
```

该接口只用于实时字幕，不生成账单，也不消耗正式语音记账次数；服务端另有独立的部分转写额度。

松手后的文字结构化：

```text
POST /v1/voice/parse-transcript
Content-Type: application/json

{
  "installationId": "anonymous-install-id",
  "transcript": "午饭25，打车18",
  "timezone": "Asia/Shanghai",
  "categories": [...]
}
```

该接口调用 DeepSeek 生成账本草稿，消耗一次正式语音记账额度；字段完整时客户端立即写入 SQLite，异常时才进入修正或确认。

```text
POST /v1/voice/parse
Content-Type: multipart/form-data

audio
timezone
locale
categoryTree
anonymousInstallId

Response:
{
  "requestId": "uuid",
  "transcript": "午饭25，打车18",
  "entries": [
    {
      "type": "expense",
      "amountMinor": 2500,
      "categoryPath": ["餐饮", "午餐"],
      "occurredAt": "2026-10-19T04:31:00Z",
      "note": "午饭"
    }
  ],
  "unresolvedFields": [],
  "latencyMs": 2180
}
```

服务端负责 ASR、结构化解析和额度校验，客户端不持有模型密钥。`requestId` 必须贯穿日志与客户端结果卡，方便定位问题，但日志不得记录账单正文。

## 8. 质量目标

- 金额准确率 ≥ 98%。
- 收支类型准确率 ≥ 95%。
- 一级分类首选准确率 ≥ 90%。
- 5 笔以内多笔完整性 ≥ 95%。
- 语音 P50 ≤ 3 秒，P95 ≤ 5 秒。
- 额度、网络和解析失败均不得造成已有账本损坏。

## 9. 固定测试集

至少 200 条真实口语，覆盖：

- 单笔/多笔、支出/收入。
- 中文数字、小数、块角元和计算表达。
- 今天、昨天、前天、周几、具体日期。
- 噪声、句尾吞字、方言口音和同音词。
- 缺失金额、多个可能金额、金额为零或负数。
- 自定义分类、相似分类和别名冲突。

每次更换 ASR 或模型供应商都运行同一测试集，不能只看演示样例。
