# 声账后期产品战略

日期：2026-10-20
状态：执行基线
适用范围：M5 之后的语音质量、月末回顾、数据安全、会员与增长

## 1. 这份文档解决什么问题

声账已经具备本地记账、分类管理、月度统计和真实语音链路。下一阶段的主要风险不再只是“功能有没有做出来”，而是：

1. 用户是否真的相信一句话记账；
2. 用户是否会为了月末回顾而持续回来；
3. 声账能否在不伤害核心体验的前提下覆盖 AI 成本；
4. 新模型或新开发者接手时，能否从仓库理解为什么这样做。

本文件是后期产品的方向和取舍入口。具体交互、接口、数据模型和测试仍以对应专项文档、契约与自动化测试为准。

## 2. 当前事实

- 200 条中文 TTS 自动化评测已通过，金额、类型、分类、日期和缺金额指标均为 100%。
- 松手到结构化完成约 P50 1.68 秒、P95 2.20 秒，详见 [语音评测报告](./20-voice-eval-report.md)。
- 当前自动化数据是合成语音，不等于真人、噪声、口音和弱网环境。
- 移动端已有本地 SQLite、手动记账、分类、删除撤销和月度统计。
- 真实微信登录、云备份、JSON/CSV 导出和真人真机矩阵尚未完成。
- 微信登录、微信支付、支付宝支付和个人开发者主体边界已完成官方核验，见 [账号、会员与支付可行性](./25-account-and-payment-feasibility.md)。
- M7 自动保存代码已落地，结果卡改为“已记好 + 8 秒撤销”；真机验证仍待完成。
- 可重复运行的成本看板已建立在 `services/api/testdata/voice/cost-report.json`；目前只覆盖 ASR 情景，完整单位经济仍待供应商账单。

## 3. 战略主线

声账后期只围绕三件事投入：

> 把一句话记账做到可信，把月末回顾做得有感觉，把数据安全做成品牌。

### 3.1 一句话记账做到可信

可信不等于“模型永远正确”。用户真正需要的是：

- 说完就记，不增加确认步骤；
- 记错了能立刻整批撤销；
- 缺金额时明确停下来，不猜测；
- 网络或供应商失败时不破坏已有账本；
- 分类和日期可以修改，修改后统计立即一致。

默认路径是“自动保存 + 8 秒撤销”。只有金额缺失、结构异常或用户主动选择“每次先确认”时，才进入确认或修正。

### 3.2 月末回顾做得有感觉

月末回顾不是增加更多财务指标，而是帮助用户用很低的理解成本回答：

- 这个月的钱主要花在了哪里；
- 哪一天或哪一类支出和平时不一样；
- 我用语音省下了多少操作；
- 下个月我想记住什么。

首版回顾必须可由本地统计数据确定生成，不依赖大模型。AI 只可以在后期把确定事实写得更自然，不能编造用户没有的数据。

### 3.3 数据安全做成品牌

数据安全要成为可被用户复述的承诺，而不只是隐私政策里的一段文字：

- 录音只用于本次识别，完成后丢弃；
- 转写文本不进入日志，不用于训练；
- 本地账本是主数据源；
- 游客不登录也能完整记账；
- 用户可以随时导出，不把数据当人质；
- 云备份按账号隔离、加密存储、可恢复、可删除。

对外文案必须与实现、日志和第三方 SDK 行为一致。不能把“云端识别”宣传成“完全离线”。

## 4. 北极星指标

北极星指标：

> 每周至少 3 天有有效语音记账的用户数。

它同时检查“有记账行为”和“语音已经成为习惯”，比下载量、注册量或单日 DAU 更接近产品价值。

辅助指标：

| 层级 | 指标 | 进入下一阶段的建议门槛 |
| --- | --- | --- |
| 激活 | 首次记账完成率 | ≥ 80% |
| 激活 | 首次会话语音使用率 | ≥ 60% |
| 可信 | 语音松手到结构化 P95 | ≤ 5 秒 |
| 可信 | 语音金额准确率 | ≥ 98% |
| 可信 | 语音异常态可恢复率 | 100% 有明确出口 |
| 留存 | 第 7 日留存 | ≥ 25% |
| 成本 | 每活跃用户月成本 | 可由成本看板解释 |
| 商业 | 付费转化或创始人包购买率 | 1%–3% 作为首轮观察区间 |
| 传播 | 被邀请人 7 日内激活率 | 不只看邀请数 |

## 5. 阶段路线

| 阶段 | 用户要得到什么 | 主要交付 | 进入下一阶段的门槛 |
| --- | --- | --- | --- |
| M5 质量基线 | 真实说话也能记对 | 30–50 条真人语音、双端真机、12–15 人封闭试用 | P0 缺陷为 0；语音和统计一致 |
| M6 可发布 MVP | 能稳定安装、记账、统计和带走数据 | 本地导出/恢复、语音生产网关、商店材料 | 双端生产构建可安装 |
| M7 可信的一句话 | 松手即入账，错了能马上撤销 | 自动入账、异常确认、结果卡状态机 | 默认路径无需第二次确认 |
| M8 有感觉的月末回顾 | 月底愿意打开看一眼并分享 | 月度回顾、隐私可控分享卡 | 回顾打开率和分享预览完成率 |
| M9 数据安全品牌 | 清楚知道录音和账本怎么被保护 | 隐私中心、备份状态、删除与导出证明 | 文案与实现、日志、SDK 清单一致 |
| M10 创始会员 | 愿意为更多价值和长期使用付费 | 19.9 元限量创始支持包、权益与额度 | 有真实付费和退款数据 |
| M11 可持续增长 | 分享带来高质量新用户 | 激活制邀请、月报分享、ASO 和内容实验 | 付费投放前留存与单位经济成立 |

## 6. 为什么是这个顺序

### 先可信，再回顾

月末回顾建立在账单可信之上。语音准确、撤销可靠和统计一致没有解决时，越漂亮的报告只会放大错误。

### 先回顾，再会员

会员需要先有“不买会失去什么”的真实价值。月末回顾、云备份历史、年度报告和更多语音额度，比一个空的会员标签更容易解释。

### 先安全，再增长

分享账单和邀请朋友都涉及信任。隐私边界不清楚时做传播，会把一次产品失误变成公开事故。

### 先激活制，再大规模邀请

邀请奖励必须奖励“形成习惯的人”，不能奖励“安装后离开的人”。分享是留存成立后的放大器。

## 7. 商业原则

- 手动记账、本地账本、基本统计和导出不设付费墙。
- 免费版保留足够的语音额度，保证用户能体验核心价值。
- 会员主要卖更多 AI 额度、数据安全增强、深入回顾和长期便利。
- 不卖“无限 AI”承诺，不使用“终身无限”作为标准价。
- 19.9 元只作为限量创始支持包，建议包含 12 个月 Pro，而不是永久无限语音。
- 邀请奖励采用双方各 30 天 Pro，被邀请人完成有效记账后到账。
- 不做广告、排行榜、现金返现、多级分销或消费羞耻式营销。

详细规则见 [会员与增长方案](./23-membership-and-growth.md)。

账号身份与支付渠道解耦：会员绑定内部 `userId`，不绑定微信身份。iOS 数字会员优先使用 Apple 内购，微信/支付宝 APP 支付等经营主体就绪后再评估。

## 8. 近期不做

- 预算、资产、负债、投资和家庭共享；
- 银行或支付平台自动导入；
- 无尽 AI 聊天；
- 用户消费排名和强迫式连续签到；
- 关系链和公开账本；
- 在真人评测和留存证明之前大规模买量；
- 在没有成本看板时公开承诺长期不限量权益。

## 10. 需要继续验证的决策

| 决策 | 为什么还没定 | 需要的证据 |
