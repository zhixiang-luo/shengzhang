# MVP 验收标准

## 1. 验收原则

MVP 完成不是“页面能打开”，而是用户能在 iPhone 和安卓真机完成完整核心流程，数据正确、异常可恢复、隐私边界清楚，并具备提交应用商店的条件。

## 2. 功能验收

### 游客与首次使用

- [ ] 首次启动不要求登录。
- [ ] 30 秒内可以找到并触发第一笔记账。
- [ ] 拒绝麦克风后仍能手动记账。
- [ ] 首笔记完后登录提示只出现一次，可跳过。

### 语音

- [ ] 按住录音、松手提交、上滑取消均可靠。
- [ ] 单笔和多笔解析正确并自动保存。
- [ ] 一句话 5 笔可保存，超过 5 笔不保存并提示拆分。
- [ ] 8 秒内可撤销本次生成且未修改的账单。
- [ ] 缺金额时不落账，补齐后可保存。
- [ ] 网络失败、额度耗尽和权限拒绝均提供恢复路径。
- [ ] 设置中可切换自动入账与先确认。

### 手动记账与账本

- [ ] 支出/收入、金额、分类、日期和备注可保存。
- [ ] 金额计算正确，按分存储无浮点误差。
- [ ] 编辑、删除和短时撤销正常。
- [ ] 月份切换和日期分组正确。

### 分类

- [ ] 内置分类完整可用。
- [ ] 自定义分类可新增、改名和排序。
- [ ] 已被引用的分类不能直接删除，归档后历史账单仍正确显示。
- [ ] 语音别名映射到标准分类。

### 统计

- [ ] 月度支出、收入、结余与账单明细一致。
- [ ] 每日柱状图可点击进入对应日期。
- [ ] 分类占比和笔数正确。
- [ ] 较上月、日均和最大支出日计算正确。
- [ ] 无数据月份显示合理空状态。

### 登录与云备份（后续版本，不阻塞免费首发）

以下项目在账号、身份和外部主体就绪后验收，不作为免费本地首发的发布门禁：

- [ ] 微信移动端一键登录可完成授权、取消、未安装和网络失败流程。
- [ ] 登录后游客账单和分类全部进入首份备份。
- [ ] 本地变化触发自动备份，失败不阻塞记账。
- [ ] 新设备本机为空时可恢复。
- [ ] 两边都有数据时必须明确选择，不静默覆盖。
- [ ] 退出登录后本机账本保留。

### 数据管理

- [x] 自动化验证 JSON 导出格式、数量、引用、校验值和真实 SQLite 覆盖恢复。
- [x] 自动化验证恢复写入失败后旧账本完整保留。
- [ ] Android/iOS 真机完成“导出 → 清空 → 恢复”闭环。
- [x] 自动化验证 CSV UTF-8 BOM、中文表头、字段转义和公式注入防护。
- [x] 自动化验证清空后恢复完整内置分类。
- [ ] 从系统分享面板实际保存 JSON/CSV，并通过系统文件选择器导入。
- [x] 清空本机账本需要两次明确确认。
- [ ] 删除后不会因未来自动备份重新上传旧数据；该条等待云备份功能实现后验收。

### 账单搜索

- [x] 账本右上角提供不小于 44×44 的搜索入口。
- [x] 未设置条件时按时间倒序展示最近有效账单。
- [x] 关键词可匹配备注、一级分类和二级分类。
- [x] 收支类型、分类、日期和金额范围可组合筛选，语义为 AND。
- [x] 元金额通过 `parseYuanToCents` 转为整数分后比较。
- [x] 反向日期、反向金额和非法金额显示中文错误，不展示误导结果。
- [x] 自动化验证开始/结束日期由月历选择结果写回，空值以当前本地自然日打开，只选日期时不携带时分。
- [x] 搜索离线可用，点击结果打开真实账单编辑。
- [ ] Android/iOS 真机验证中文输入法、键盘避让、窄屏和 5000 笔账单性能。
- [ ] Android/iOS 真机验证日期选择 Sheet、取消不修改条件、单个日期清除，以及搜索与金额输入文字垂直居中。

### 月度回顾与分享

- [x] 统计页在空月份和非空月份都提供 44×44 以上的回顾入口。
- [x] 回顾支出、收入、结余、分类和上月比较使用本地整数分领域规则。
- [x] 当前月按已过去天数、历史月按完整天数计算日均。
- [x] 最高支出日金额并列时选择较晚日期。
- [x] 空月份返回固定空文案和手动记账出口。
- [x] 分享前必须先打开 App 内预览。
- [x] 默认分享摘要不含金额、备注、商户、分类名和精确日期。
- [x] 分享 PNG 目标尺寸为 `1080×1350`，临时文件在调用结束后清理。
- [x] 系统分享取消不记为失败，也不虚构“已发送”事件。
- [ ] Android/iOS 真机验证 PNG 清晰度、系统分享、取消分享和原生模块。
- [ ] 小屏、动态字体和长文案下检查回顾页、预览弹层与按钮不被截断。

## 3. 语音质量验收

固定测试集至少 200 条，覆盖中文数字、小数、相对日期、收入、多笔、自定义分类、噪声、同音词、缺失金额和无效输入。

| 项目 | 门槛 |
| --- | --- |
| 金额准确率 | ≥ 98% |
| 收支类型准确率 | ≥ 95% |
| 一级分类首选准确率 | ≥ 90% |
| 多笔完整性 | ≥ 95% |
| P50 延迟 | ≤ 3 秒 |
| P95 延迟 | ≤ 5 秒 |

更换 ASR、模型、提示词或分类映射后必须重新执行完整测试集。

## 4. 双端与兼容性

- iOS 与 Android 的主流程、文案和视觉层级一致。
- 在至少一台小屏 iPhone、一台主流 iPhone、一台主流 Android 真机验证。
- 检查系统动态字体、键盘遮挡、安全区、深色系统下的可读性。
- 麦克风和网络切换后不崩溃、不重复落账。
- App 杀进程后本地账单仍存在。
- 登录态过期后可刷新或重新登录，不丢失本地数据。

## 5. 无障碍

- 语音主按钮有明确可读标签和按压状态。
- 所有触控目标不小于 44×44pt。
- 文本与背景对比度至少 4.5:1。
- 图表关键数据同时以文字列出。
- 不只依赖颜色表达支出/收入、成功/失败。
- 支持系统动态字体，不截断金额和主操作。

## 6. 性能与稳定性

- 冷启动到可交互不高于 2 秒（主流设备）。
- 5000 条账单下列表滚动和月度统计保持流畅。
- 语音请求取消或退后台后不产生幽灵账单。
- 7 日内严重崩溃率低于 0.5%。
- 备份失败不导致本机数据库锁定或损坏。

## 7. 隐私与安全

- 录音不写入持久化文件，服务端无留存。
- 日志不包含账单正文、录音、转写和 token。
- 云备份只能由所属账号下载。
- 未同意隐私政策前不初始化第三方采集。
- 切换账号时清除前一账号的访问令牌和备份缓存。
- 删除数据、覆盖恢复和退出登录均有明确确认与结果反馈。

## 8. 商店发布

- [ ] 商标和商店名称复核完成。
- [ ] 隐私政策、用户协议、权限说明可访问。
- [ ] App Store 隐私清单和 Android 数据安全声明与实际一致。
- [ ] 微信开放平台移动应用审核通过。
- [ ] iOS 与 Android 图标、启动页、截图、描述和关键词完成。
- [ ] 正式构建无测试入口、调试菜单、模拟数据或硬编码密钥。
- [ ] 至少完成一轮 TestFlight 和安卓内测。

## 9. 最终端到端场景

测试人员在新设备上：

1. 以游客身份说出“午饭 25，打车 18”。
2. 确认两笔账单自动保存并可撤销。
3. 修改一笔账单并确认统计更新。
4. 查看本月统计和当天明细。
5. 导出 JSON，清空本机后恢复。
6. 从账本进入搜索，按分类和金额范围找到刚才的账单并打开编辑。
7. 从统计进入本月回顾，确认数字一致并分享一张不含敏感账目的月卡。

全流程不得出现数据丢失、重复账单、静默覆盖、分享卡泄露默认敏感字段或无法解释的错误。

账号登录、云备份和换机恢复在后续版本单独执行端到端验收。
